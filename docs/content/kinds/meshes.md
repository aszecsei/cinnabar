# Meshes

Meshes come from `.gltf` and `.glb` files, read with `vendor:cgltf`, and from `.mesh` files that the editor builds (see [Mesh files](#mesh-files)). A glTF file is a `Model` asset, which has no blob of its own: its meshes are `Mesh` sub-assets (see [Identity](../identity-and-cooking.md#identity)), each with its GUID on a `mesh.<name>` line of the model's `.meta` file. `just models` runs `cook models --cache build/<target>/content --config dev|release` with the roots.

- **One mesh asset per glTF mesh**, named for the glTF mesh, in its own space with its own pivot. Node transforms are not baked in, so a mesh that many nodes use is one asset. Each glTF primitive becomes a submesh. Primitives that share a glTF material share a submesh, and each submesh has a material slot named for its glTF material.
- **Unnamed meshes** are named for the first node that uses them, then `mesh_<index>`.
- **Names** are keys in the `.meta` file, so an `=` in a name becomes `_`, and two meshes of one name get `_2` and on.
- **`combine = true`** makes one mesh asset, named for the file without its extension, instead: the cooker walks the default scene's nodes and bakes their transforms into the vertices. This suits a file that is one prop exported in pieces. The default is `false`.
- **Axes:** glTF is right-handed, with +y up and +z the asset's front. The engine is left-handed, with +x right, +y up and +z forward. The cooker negates x and reverses each triangle's winding, so front faces are clockwise on screen, as `lib/core/gpu` takes them, and back faces cull. The mirror flips the tangent frame's handedness, so a tangent from the file has its bitangent sign flipped too.
- **Missing attributes:** a primitive without normals gets its faces' normals, as glTF specifies. A primitive that is not triangles is left out, with a warning.
- **Vertices** are two streams, so that depth and shadow passes read only positions:

| Stream | Contents | Size |
|---|---|---|
| Positions | `f32` x, y, z | 12 bytes |
| Attributes | The normal, octahedral in a `snorm16` pair; the tangent, octahedral in a `unorm16` pair whose second value's lowest bit is the bitangent's sign (set is -1); the first UV set in `f32`; then the second UV set in `f32` and the vertex color in `unorm8`, when the file has them | 16 to 28 bytes |

- **Processing** with meshoptimizer: weld identical vertices, order each submesh's triangles for the vertex cache and the mesh's vertices for fetching, and build each submesh's meshlets and their levels of detail (see [Meshlets](#meshlets)). Indices are 16-bit when the mesh has fewer than 65 536 vertices.
- **Tangents** come from the file, or from `meshopt_generateTangents` in its MikkTSpace-compatible mode, which matches how normal maps are baked. A mesh with any primitive that has no tangents gets made tangents for all of them, so its frame is consistent.
- **Bounds:** the mesh and each submesh have an axis-aligned box and a sphere.
- **Not imported:** the node hierarchy (except with `combine`), the file's materials, textures, cameras, lights, skins and animations. A USD stage brings its materials, textures and hierarchy (see [Stages](stages.md)).
- **Import settings:** `combine` (`true` or `false`, default `false`), `scale` (`0.001`, `0.01`, `0.0254`, `0.1`, `1`, `10` or `100`, default `1`: settings are checked against a list of values, so the scale is a choice of common units), `tangents` (`file` or `generate`, default `file`) and `cluster_lod` (`true` or `false`, default `true`, see [Meshlets](#meshlets)). The settings apply to every mesh of the file. `collision` (`true` or `false`, default `true`) writes the welded triangles that a mesh collider is built from (see [Physics: Shapes](../../physics/design.md#shapes)); turn it off for a mesh that nothing collides with. `impostor` (`true` or `false`, default `false`) bakes the mesh's impostor, with frames of `impostor_size` texels a side (`32`, `64` or `128`, default `64`, see [Impostors](#impostors)).
- **The cache key** is the model's: the cooker version, the meshoptimizer version, the source path, the source, the GUID and the import settings, and for a `.gltf` file the buffer files that it names. The `mesh.` lines are not in it, because the cooker writes them; a mesh's GUID is its blob's name instead, so a new GUID cooks it. A model is up to date when every one of its meshes has a blob with its key.
- **All or nothing:** a model cooks every mesh into memory before it writes any blob, so a mesh that fails fails the model, and its meshes keep their old blobs together.
- **New and renamed meshes:** the cooker gives a mesh that has no line a new GUID and writes it into the `.meta` file, which makes one more pass. A line whose mesh is gone is a warning and stays, so a mesh renamed back gets its GUID again. A re-import drops those lines.
- **meshoptimizer** is the submodule `vendor/meshoptimizer`, pinned to a release, and `just meshoptimizer` builds it with its own CMake project. Its API is C, so the cooker binds it directly (`tools/cook/meshoptimizer.odin`). `just update-meshoptimizer <tag>` moves the pin. The cluster LOD builder is its `demo/clusterlod.h`, which is C++ behind a C API: `just meshoptimizer` compiles it from `tools/cook/clusterlod` into `cn_clusterlod.lib`, which the cooker links beside meshoptimizer. Its version is meshoptimizer's.

## Mesh files

Level geometry that the editor builds comes as `.mesh` text files (see [Mesh editing](../../editor/mesh-editing.md#mesh-assets)): a `Mesh` asset of its own, with one blob under its own GUID, which a `Mesh_Renderer` places as it places a glTF mesh. Nothing downstream tells them apart. `just meshes` runs `cook meshes --cache build/<target>/content --config dev|release` with the roots.

- **The file** starts with `mesh 1`. `material <slot> $<guid>` names a material slot, 0 to 7 (`render.MAX_MATERIAL_SLOTS`); the entity's `Mesh_Renderer` gives each slot its material anyway, so the line is for the editor. `v <x> <y> <z>` is a vertex in meters, in the mesh's space. `f <slot> <v0> <v1> <v2> ...` is a face of three or more vertex indices from 0, clockwise seen from its front, as the cooker leaves glTF faces. A face's `map` line follows it: `map <ux uy uz> <vx vy vz> <su sv> <tu tv> <rotation>`, the texture's two axes in the mesh's space, the scale in meters per texture repeat, the shift in repeats and the rotation in degrees; a face without one gets a world-aligned mapping by its normal at one repeat per meter. `e <a> <b> sharp` marks an edge sharp: normals do not smooth across it. `#` starts a comment. A line the parser does not know is a warning, so a file from a newer editor still cooks; a malformed line, a face of fewer than three indices or an index that no vertex has is an error.
- **Two parsers,** `format.mesh_text_parse` in `lib/engine/asset/format/mesh_text.odin` for the cooker and the game, and `MeshFile` in `Cinnabar.Editor.Mesh` for the editor, read the same lines and must agree, as `scene_parse` and `SceneFile` do. Each has a writer, which puts the vertices first, then the faces in order with their map lines, then the sharp edges, and writes a number as the shortest decimal that reads back as the same f32, so a round trip changes nothing and an edit changes the lines of the face it touches.
- **The bake,** `format.mesh_bake` in `mesh_bake.odin`, turns the faces into the two vertex streams and the triangles once, so the cooker and the game produce the same vertices. A face's normal comes from its plane, by Newell's method. A corner's normal is the angle-weighted average of the normals of the faces around its vertex that it reaches without crossing a sharp edge. Its UV comes from the mapping: `u = (p · UAxis) / scale.u + shift.u`, likewise `v`, with the rotation turned about the mapping's origin. Its tangent is the mapping's u direction projected onto the face's plane, with the bitangent's sign from the v direction, so a normal map on a planar mapping is exact. Corners weld where their attributes agree, as a glTF cook's weld leaves them. A convex face is a fan, and a concave one is ear clipped in its plane. There is one submesh for each slot up to the highest that a face uses, so a submesh's index is its slot, and a slot that no face uses is empty. The bake also gives the polygon edges as vertex pairs, for the editor's overlay. A face with fewer than three distinct vertices, without area, with a mapping scale of 0, or that cannot be triangulated is a warning at its line, and the mesh bakes without it.
- **The cook** (`tools/cook/mesh_files.odin`) parses, bakes, then runs the glTF path's second half unchanged, `finish_mesh` in `meshes.odin`: weld, cache and fetch order, meshlets and their levels, bounds and the blob. A submesh is named for its slot's number. A file with an error keeps its old blob.
- **Import settings:** `tangents` (`generate` or `mikk`, default `generate`: the mappings' tangents, or MikkTSpace ones from `meshopt_generateTangents`) and `cluster_lod` as glTF models have it. There is no `scale`: a `.mesh` is already in meters. `collision` (`true` or `false`, default `true`) writes the welded triangles that a mesh collider is built from (see [Physics: Shapes](../../physics/design.md#shapes)); turn it off for a mesh that nothing collides with. `impostor` and `impostor_size` as glTF models have them.
- **The cache key** is the cooker version, the meshoptimizer version, the source path, the source, the GUID and the import settings.
- **New meshes** come from the content browser's New Mesh, which asks the daemon's `Create_Asset` for the `mesh` template: a 1 m box on the origin's corner, each face with a world-aligned mapping and every edge sharp, as the editor's Block tool makes. The sample's `meshes/room.mesh` is a room, a pillar and a partition wall written by hand, each a closed box, which `scenes/room.scene` places; F7 in mygame cycles to it.

## Meshlets

Each submesh's meshlets are a hierarchy of levels of detail, which the [mesh shader path](../../rendering/gpu-scene.md#mesh-shader-path) draws a cut of: the coarsest level of each part of the mesh whose error does not show. The cooker builds it with meshoptimizer's `clodBuild` (`build_meshlets` in `tools/cook/meshes.odin`), after Nanite.

- **Levels.** Level 0 is the submesh's own triangles, in meshlets of at most 64 vertices and 124 triangles. Each level after it groups neighbouring meshlets of the level below, about 16 to a group, simplifies each group to half its triangles with the group's border locked, so that neighbouring groups still meet, and splits the result into meshlets again. A group that cannot lose a sixth of its triangles is the top of its part of the hierarchy. The meshlets are in order of level.
- **Errors.** Each meshlet keeps the bounds of the simplification that made it, a sphere and an error, 0 at level 0, and of its own group's simplification a level up, whose error is `F32_MAX` at the top. A group's error is at least each of its meshlets' errors, so errors grow up the hierarchy. For any threshold, the meshlets whose own error is at most the threshold and whose group's error is more cover the submesh once: one level of each part, without cracks or overlaps. The cooker's tests check that at several thresholds.
- **Simplification** keeps vertices where they were, so meshlets of every level index the mesh's one vertex buffer and no level adds vertices. It weighs the normals, 0.5 for each component, as meshoptimizer's demo does, and keeps both UV sets' seams.
- **Culling bounds** are each meshlet's own: `meshopt_computeMeshletBounds` gives its sphere and its normal cone, in `snorm8` with meshoptimizer's conservative cutoff, which is 127 for a cone too wide to cull. `clodBuild` clusters without a weight on the cones, so they are wider than those of `meshopt_buildMeshlets` with one.
- **The record**, `format.Meshlet`, is 80 bytes that shaders read as they are: the vertex and triangle offsets, the vertex and triangle counts and the level, the cone, the culling sphere, and the two simplifications' spheres and errors. A meshlet's vertices are `u32` indices into the mesh's vertices. Its triangles are one `u32` each, the three indices into its vertices in the low three bytes, because shaders load whole aligned words.
- **`cluster_lod = false`** makes level 0 only, with `meshopt_buildMeshlets` and a cone weight of 0.25, and each meshlet's group error is `F32_MAX`, so the same shaders draw it. It suits a mesh whose simplification looks wrong, such as one whose silhouette must not change.
- **Size:** the preview sphere, 3968 triangles, has 45 meshlets at level 0 and 97 in all over seven levels; a level holds about half the triangles of the one below, so the hierarchy is about twice the size of level 0. The mesh's indices for vertex pulling stay, at level 0.

## Impostors

A mesh whose import setting `impostor` is `true` has an octahedral impostor in its blob: the mesh seen from all around, which the [impostor path](../../rendering/gpu-scene.md#impostors) draws as one quad past the mesh's coarsest level of detail. `finish_mesh` bakes it after the meshlets (`bake_impostor`, in `tools/cook/impostors.odin`), on the CPU, from the welded vertices.

- **Frames.** `IMPOSTOR_FRAMES` (8) by 8 frames. Frame (x, y) looks from the direction that the point (x, y) / 7 × 2 − 1 of the square unfolds to from the octahedron, as normals unfold, so the grid's corners and edges are views too and a view between grid points blends the three nearest. Each frame is an orthographic view of the mesh's bounding sphere along that direction, with its right across the world's +y, or across +z when it looks along y, `impostor_size` texels a side (`32`, `64` or `128`).
- **Texels** (`format.Impostor_Texel`, 16 bytes): the first UV set in two halves, the depth toward the frame's viewer from the plane through the sphere's center in radii as a half, the submesh's index plus 1 in the low byte of the flags, 0 where the frame sees nothing, with `IMPOSTOR_TEXEL_FLIP` where the bitangent's sign is -1, and the normal and tangent, octahedral in snorm16 pairs, in the mesh's space. The bake rasterizes every triangle of every submesh at the texels' middles and keeps the nearest; a triangle seen from behind gives its normal flipped, as a two-sided material shades it.
- **The blob** has the atlas, frame by frame, each row by row, `impostor_size`, and `impostor_error`: how far the impostor may be from the mesh, in meters, the larger of the coarsest level's error, the largest error of the meshlets at the top of the hierarchy, and a texel, the sphere's diameter over the size. The runtime switches to the impostor where that error does not show. An atlas of 64 texels is 4 MB.
- The sample's `meshes/tower.mesh` bakes one.
