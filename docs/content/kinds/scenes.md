# Scenes

Scenes are `.scene` text files (see [Editor](../../editor/document-and-scenes.md#scenes)). `just scenes` runs `cook scenes --cache build/<target>/content --config dev|release --root game=<content root>`. The cooker cannot lay out native components, because their types exist only in the game DLL, so it checks only the file: its syntax, and that the scene IDs and the script GUIDs that it names exist. A missing one is a warning. A reference to an entity of another scene (`@<guid>/<id>`) is checked by its GUID alone: the cooker warns when the GUID is not a scene in the content, and does not read that scene. The target is not a dependency, because the scene loads without it. A reference to the scene's own GUID is written as a local one. A prefab has no scene of its own, so each of its references to another scene is a warning and becomes none. The cook version is `scenes 5`, so every scene cooks again after this change. A scene with an error keeps its old blob. The cache key covers the cooker version, the configuration, the source path, the source and the `.meta` file's GUID and settings.

The same pass cooks `.prefab` files, the scenes with one root that other scenes instantiate ([Prefabs](../../editor/prefabs.md)). It cooks them first, since a scene's cook expands its instances with `asset_format.scene_expand`. Both kinds cook to flat scene blobs, a prefab's under the `Prefab` kind, so the loader never sees an instance. A scene's key also covers the source of every prefab that it reaches, so saving a prefab cooks the scenes that use it again, and its dependencies name the prefabs that it instantiates. A prefab without exactly one root, a cycle of prefabs, a nesting more than eight deep and an instance of an asset that is not a prefab are errors; a missing prefab and an override whose entity is gone are warnings. See [Prefabs](../../editor/prefabs.md#cooking).

A scene's navigation volumes make navmeshes, its sub-assets, one for each volume and agent type, `navmesh.<volume>.<agent type>` in its `.meta` file. The scene's cook gives them their GUIDs and lists them in its blob, and `cook navmeshes` bakes them after the meshes cook. The scene's key covers the list and leaves the `.meta` file's sub-asset lines out. See [Navmeshes](nav-meshes.md#sub-assets).

## Sublevels

The runtime loads and unloads whole blobs, so the cooker splits a scene into one blob for each part: its base, and each sublevel that its entities are in (see [Editor: Sublevels](../../editor/document-and-scenes.md#sublevels)). The runtime sees each part as a scene ([World: Sublevels](../../world/sublevels.md#parts-are-scenes)).

- **Sub-assets:** each sublevel of a scene is a sub-asset, `sublevel.<name>` in the scene's `.meta` file, with its own GUID and blob (see [Sub-assets](../identity-and-cooking.md#identity)). Its blob is a scene blob, whose header has the sublevel's GUID. The base keeps the scene's GUID, so a scene without sublevels cooks to one blob, as before, and every reference to it still holds.
- **The list:** the base's blob lists the scene's sublevels by name, each with its GUID (`asset_format.scene_sublevels`), so a loader finds them without the `.meta` file. A sublevel's blob lists none.
- **Scene IDs** do not change, so `@<guid>/<id>` and prefab paths still find their entities. Each part keeps its entities in the file's order. A parent and its children are always in one part.
- **References across parts:** a reference from one part to an entity of another becomes a reference across scenes to that part's GUID, `@<guid>/<id>`, so it binds and unbinds as the part loads and unloads (see [References across scenes](../../world/scenes.md#references-across-scenes)). A reference to the base names the scene's GUID. A reference that stays in its part stays local, also one that the file writes with the part's own GUID.
- **Navmeshes:** a navigation volume's navmeshes are in the list of the part that has the volume, so they load and unload with it. The bake still reads the colliders of every part.
- **The key:** one key covers every part. It covers the source, which says which part each entity is in, and the sublevels' names and GUIDs. The scene is up to date only when every part's blob has the key, so a change of an entity's sublevel cooks the scene and its parts again.
- **A sublevel that the scene no longer uses** loses its blob, which the cook deletes. Its `.meta` line stays, with a warning, as other sub-assets' lines do, so the sublevel gets its GUID again if it comes back.
- **Bundles:** in a release, a sublevel's blob is in its scene's bundle: the chunk's bundle for a streamed scene, and the level's bundle otherwise (see [Bundles](../blobs-and-loading.md#bundles)).
- A stage's generated scene has no `.meta` file to keep the GUIDs in, so it does not split. A prefab never does, as its entities are in the sublevel of each instance.
