# Material editor

The material editor edits a material's graph or a material function (see [Content pipeline](../content/kinds/materials.md#material-graphs) and [Rendering](../rendering/materials.md#materials)). Each open one is a document beside the viewport, `MaterialEditorDocument`, over a `MaterialEditor` in the shell, which holds its state, so docking can rebuild the view, and tests drive the editor without a window.

- **Layout:** the material's settings over the canvas (the shading model, the blend and its cutoff, two-sided, casts shadows), with the save button, and the material's status on the right: its permutations from the index, whether the preview's cook is up to date or what failed, and unsaved changes. On the left, the preview over the parameters and static switches; on the right, the selected node's details. A material function has its canvas and details only.
- **The catalog:** the kinds of node come from the cook daemon's `Welcome` and the shading models from its `Shading_Models`, so the editor knows no kind of node of its own. A node's inputs and outputs come from its kind, or for the output node from the shading model's surface inputs, for a parameter node from its parameter's type, and for a function node from the function's file, which the editor reads (`MaterialCatalog`).
- **The canvas** (`GraphCanvas`) draws each node with a header in its category's color, its inputs on the left and its outputs on the right, each pin in its type's color, filled when linked, and an unlinked input's value or default beside it. Links are curves in their output's color. A node that the preview's cook reports an error on has a dashed red frame. The canvas's geometry and hit test are `GraphGeometry` in `Cinnabar.Editor.Tools`.
- **Mouse and keys:** the left button selects a node (Shift adds, Ctrl toggles), drags the selected nodes, drags a box, and drags a link from an output to an input or back; a link dragged off an input moves to another input or is removed, and one dropped on nothing opens the node picker and links to the new node's first input or output that fits. The right or middle button pans, and a right click without a drag, Space or Tab opens the node picker. The wheel zooms about the mouse. Delete deletes the selected nodes, but not the output node, Ctrl+D duplicates them with the links between them, F frames the graph, and Escape cancels a drag. Double-clicking a function node opens its function. A link that would make a loop is refused.
- **The node picker** searches the kinds of node that the graph can have by label, category and description; Enter adds the first match where the mouse was.
- **Details:** the selected node's properties, each with an editor for its kind (numbers, a color with its swatch, text, HLSL, a choice, or a parameter, a switch or a function by name), and its inputs: a linked input names its link, and an unlinked one takes numbers, empty for its default. Below them, the node's problems.
- **Parameters** have a name, a type, a default and a group, and **static switches** a name and whether they are on; a new name renames them in the nodes that read them, and the arrow adds a node that reads them.
- **Undo:** each material editor has its own undo stack of the graph's text before and after each edit (`MaterialDocument`), and a drag is one entry. Undo, Redo and Save act on the material editor whose document is active, and on the scene otherwise. A document is dirty when its position in its history is not the one that its file has, and its tab marks it with a dot.
- **Saving** writes the graph's text through a temporary file, as a scene saves, and the cook daemon then cooks it. The writer puts each node on lines of its own, sorted as the graph has them, and keeps the comment lines after the version line.
- **Closing** a material editor with unsaved changes asks to save them, and so does closing the editor.
- **The preview** (`PreviewPane`): a material's editor has one of the game's previews, at most four at once with the effect previews, which a `ViewportSession` of its own copies as the viewport's frames are copied, and acknowledges with `Preview_Acknowledged`. Dragging turns its camera about the mesh, the wheel moves it nearer, and the buttons pick a sphere, a cube or a plane. The editor sends `Open_Preview` and `Preview_Settings` when the preview opens and when the host links, and `Close_Preview` when it closes.
- **Unsaved graphs:** a moment after each change, and when it opens, the editor sends the graph's text to the cook daemon in `Cook_Preview`. Once one cooks, the editor opens the preview again with `unsaved`, so the game shows the preview area's blob. The answer's problems go on their nodes, by the lines that the writer gave each node, and the others on the material.
