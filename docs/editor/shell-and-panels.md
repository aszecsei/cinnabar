# Shell and panels

Docking and workspaces, the ribbon, the Add menu, commands and game commands, and each panel: the outliner, properties, the sublevels, the atmosphere, the weather map, the resource monitor, the profiler and the content browser.

**In this document:** [Shell](#shell) · [Panels](#panels)

## Shell

- **Docking:** the Dock library for Avalonia. The default layout is the outliner on the left, the Scene and the Game as two tabs in the middle, the Scene in front, the properties, the Face panel, sublevels, undo history, atmosphere and weather map on the right, and the console, content browser, resource monitor and profiler at the bottom. It is the preset of the General workspace (see [Workspaces](#workspaces)).
- **One instance of each panel.** Closing a panel takes it out of the layout, and showing it again puts the same panel back in its default dock, so its state survives. Docking can rebuild a panel's view at any time, so a view holds no state: the console's lines are in a `ConsoleLog`, and a viewport's device and frames are in its `ViewportSession`.
- **The console keeps up with a flood.** The game's and the cook daemon's log lines come on the link's thread. They wait in a `LogQueue`, which holds at most 5,000 lines and drops the oldest past that. One post takes all the lines that came since the last post to the UI thread, so a process that logs on each frame costs one post a batch, not one a line. `ConsoleLog.AddRange` adds a batch as one change, keeps the newest 5,000 lines, and puts a warning that says how many lines were dropped. The console scrolls to the end once a batch. A game that logs thousands of lines a second therefore cannot fill the UI thread or the editor's memory.
- **The layout file:** the editor saves the layout to `layout.json` when it closes, and with it `workspaces.json`, which says which workspace the layout is of (see [Workspaces](#workspaces)). The file is the editor's own: the tree of splits, tool docks and document docks, with proportions, panel IDs, and for each document dock the documents it holds (`scene` and `game`) and its active one. Dock's serializer would store Dock's types, and need metadata for each. A panel that floats docks again in its default dock at the next start, and panels cannot be pinned. A file from an editor with one viewport has a document dock that lists no documents, which restores as the Scene and the Game. A layout that has no document dock, or that does not parse, is replaced by the default with a warning in the console.
- **Documents:** the Scene, which holds the scene views that are on, and the Game are documents, each once. They tab, split and close like other documents, the last one included, and do not float or move into a tool dock. The Scene has a tool strip down its left edge, for the tool and the mode of every scene view (see [Tool strip](viewport.md#tool-strip)). Each viewport has a toolbar, whose menus change that viewport: in a scene view, its Layout menu has a toggle for each of the four views and the presets that set the toggles, and its View menu has the view's projection (see [Toolbar](viewport.md#toolbar)). The Window tab's Scene View and Game View show or hide each document (see [Viewport](viewport.md#views)). The material editor's, the animation graph editor's and the UI editor's documents go beside them, in the document dock that holds the Scene, or else the Game (see [Material editor](material-editor.md#material-editor), [Animation graph editor](animation-graph-editor.md#animation-graph-editor) and [UI editor](ui-editor.md#ui-editor)); the layout file does not keep them.
- **Asset editors:** the material, animation graph, UI, decision, blackboard, World and cutscene editors are rows of one table, `EditorShell.GraphEditorKinds`. A row says which asset kinds it opens, how it reads the file, what editor and view it makes, whether the editor takes a preview slot, and what its close ends. The shell opens, shows and closes every kind by one path, `EditorShell.OpenEditor`, and keeps the open editors in one list, in the order that they were opened or shown again. Each is a `GraphEditorDocument` whose ID is the row's prefix and the asset's GUID, such as `cutscene.{guid}`. A new kind of asset editor is a row, an editor and a view. Assets from the command line and assets that the content browser makes wait in one queue, and open as a double click does once the index has them.
- **Status bar:** the host's state and the cook daemon's state, with a reason or an exit code: waiting for the viewport (the host only), starting, linking, running or watching, link lost, refused, timed out, cannot start, stopped, or exited (see [Crash recovery](processes-and-projects.md#crash-recovery)). The tooltip has the whole text. Then the scene's file, the entity count, the selection, and the mode.
- **Theme:** dark, with one accent color, cinnabar (`#E34234`), also in Dock's brushes. Play mode tints the shell. Icons are Fluent UI System Icons (MIT), as path data in `Icons/Icons.axaml`, so the editor depends on no icon package.
- **Errors:** an exception that no code handles on the UI thread goes to the console, and the editor keeps running. A bug in one panel must not close the editor and lose unsaved work.

### Workspaces

A workspace is an arrangement of the panels for one kind of work, with the ribbon tab that the work mostly uses (`Workspace`, `Workspaces` and `WorkspacePresets` in `Cinnabar.Editor.Docking`). One workspace is active. [Users and workflows](workflows.md#what-each-user-reaches) says which kind of user each one is for.

| Workspace | ID | Its preset | Ribbon tab |
|---|---|---|---|
| General | `general` | The default layout, with every panel | Home |
| Level Design | `level` | The outliner on the left. The content browser and the console under the Scene and the Game. The properties, the Face panel, the sublevels and the undo history on the right. | Home |
| Environment Art | `environment` | The outliner on the left. A tall content browser under the Scene and the Game. On the right, the properties and the undo history over the Face panel. | Environment |
| Lighting | `lighting` | The outliner on the left. The resource monitor and the console under the Scene and the Game. On the right, the properties and the undo history over the atmosphere and the weather map. | Lighting |
| Scripting | `scripting` | The outliner on the left. The Scene and the Game side by side, over a tall dock with the console, the content browser and the profiler. The properties and the undo history on the right. | Scripting |
| Cinematics | `cinematics` | The outliner on the left. The Scene and the Game side by side, over the editors' dock, where the [cutscene editor](cutscene-editor.md#the-tab) and the other asset editors open. The properties and the undo history on the right. | Gameplay |
| Performance | `performance` | Under the Scene and the Game, the profiler and the console beside the resource monitor. The properties and the outliner on the right. | Scripting |

- **A panel that a workspace leaves out** is closed, not gone. The Window tab's Panels group shows it again.
- **Switching** keeps the arrangement that the user leaves, and restores the other workspace as the user left it, or as its preset the first time. The ribbon then shows the workspace's tab. A kept arrangement that does not restore, as one from an editor with other panels, gives way to the preset. `EditorShell.SwitchWorkspace` is the one place that switches: it calls `Workspaces.Switch`, and asks the ribbon for the tab. The asset editors' open tabs are not in an arrangement, so they move to the new arrangement's editors' dock, `EditorLayout.EditorDocumentsDock`, or beside its scene view.
- **Reset Layout** puts the active workspace back to its preset.
- **Commands:** `window.workspace` is a choice of the workspaces, which the box beside the ribbon's tabs and the Window tab's Workspace group show. `window.workspace.<id>`, such as `window.workspace.lighting`, makes one workspace the active one, for the command palette and key bindings.
- **Kept:** when the editor closes, `layout.json` has the arrangement that it closed with, which is the active workspace's. `workspaces.json`, beside it in the editor's settings, has the active workspace's ID and the kept arrangements of the others. When the editor starts, it restores `layout.json` and then reads `workspaces.json`. Without that file, or with one that it cannot read, the arrangement is the General workspace's, and a file that it cannot read is a warning in the console.

### Ribbon

The editor has its own ribbon control. The Avalonia ribbon libraries are small and not maintained much, and a ribbon that reads the command registry is not much work.

- **The ribbon is data.** A layout gives tabs, groups in each tab, and items in each group (`RibbonLayout`, which `DefaultRibbon` makes). Every item names a command ID. The ribbon has no logic of its own.
- **A tab for each kind of work.** The tabs are for the kinds of user that the editor has (see [Users and workflows](workflows.md#who-the-editor-is-for)), in this order:

  | Tab | Band | Groups and their commands |
  |---|---|---|
  | Home | | Scene: Open Scene, Save, Save As, Save All Scenes, Add Scene, Close Scene. Edit: Undo, Redo, Duplicate, Delete, Select All. Add: the Add menu, Empty Entity, Mesh, Camera (see [Add](#add)). Visibility: Hide, Show All, Lock. Prefab: Make Prefab, Open Prefab, Select Prefab Asset, Make Variant, Apply All, Revert All, Unpack, Unpack Completely (see [Prefabs](prefabs.md#editing-an-instance)). |
  | Lighting | Art | Lights: Directional Light, Point Light, Spot Light, and Area Light, a menu of the quad, disk and line lights. Reflections: Reflection Probe, Capture Probe, Capture All Probes (see [Viewport](viewport.md#reflection-probes)). Volumes: Volume, a menu of the kinds of volume. Atmosphere, Sun, Sky and Weather: the atmosphere's commands (see [Atmosphere](#atmosphere)). Panels: Atmosphere, Weather Map. |
  | Environment | Art | Place: Mesh, Particle System, Sprite. New Asset: New Material, New Material Function, New Mesh, New Prefab, New Effect, New Sprite Sheet, New Folder. Panels: Content Browser, Face. |
  | Gameplay | Design | Place: Camera, Trigger, Static Collider, Rigid Body, Character, Agent, Navigation Volume, UI Document. AI: New Decision, a menu of the four kinds of decision, and New Blackboard. New Asset: New Scene, New Prefab, New UI Document, New Animation Graph, New Cutscene. |
  | Scripting | Design | Scripts: New Behaviour, New Script. Code: Build Project. Profiler: Capture Frame, Capture Worst Frame, Record Zones (see [Profiler](#profiler)). Panels: Console, Profiler, Resource Monitor. |
  | Audio | Audio | Place: Audio Source, Audio Listener. |
  | Project | | Game Window: Run Game, with Close Game in its menu, and the output mode and the quality of the project and of this machine (see [Viewport](viewport.md#quality)). Release: Export. Project: Open Project. Processes: Restart Host, with Stop Host in its menu, and Restart Cook Daemon (see [Processes and projects](processes-and-projects.md#projects)). |
  | Window | | Workspace: the workspace, Reset Layout (see [Workspaces](#workspaces)). Panels: a toggle for each panel. Documents: Scene View, Game View. Capture: Screenshot, Record Last 5 s. |

  After them come the tabs that a game's commands name, such as the sample's Game tab.
- **What the ribbon has:** commands that act on the scene, the project or the window. A command that changes one viewport is in that viewport's toolbar, and a command that changes how every scene view edits is in the Scene's tool strip (see [Users and workflows](workflows.md#where-a-control-lives)). A test checks that the ribbon has none of them.
- **Beside the tabs,** whatever tab shows and while the ribbon is collapsed:
  - the quick access commands, Play, Pause, Step and Stop, each as its icon (`RibbonLayout.QuickAccess`);
  - a box that opens the command palette, with the palette's shortcut;
  - a box that chooses the workspace (see [Workspaces](#workspaces)).
- **Item kinds:** large button, a stack of up to three small buttons, split button, dropdown, and combo box. A toggle command shows as a toggle in any of them, with a check in menus. A combo box needs a choice command, which has a list of options. The menu of a split button or a dropdown is a list of menu entries, so it can have menus under labels, as the Add menu has (see [Commands](#commands)). A dropdown can have a description, which shows in its tooltip.
- **Validation:** `RibbonLayout.Validate` finds unknown commands, in the quick access and in menus too, unknown categories, repeated tabs, items of the wrong shape and menus without commands. The shell reports them in the console, and a test checks the default ribbon.
- **Tab categories:** a tab can belong to a category with a name and a color. The category shows as a colored band over its tabs, with its name over the first tab of each run. The editor's categories are the disciplines: Art over Lighting and Environment, Design over Gameplay and Scripting, and Audio over the Audio tab. Home, Project and Window have no category.
- **Contextual tabs** have a condition, such as "a terrain entity is selected", and show only when it is true. A condition is a named context, such as `host.running`, that the editor sets. The default ribbon has no contextual tab.
- **Game commands** that the DLL describes can name a tab and a group. They appear in the ribbon, and they come and go with a code reload.
- Double-clicking a tab, or Ctrl+F1, collapses the ribbon to its tabs, and clicking a tab opens it again. When the window is too narrow, the ribbon scrolls.

### Commands

- A command has an ID such as `edit.undo`, a label, an icon, a default shortcut, a can-execute check and an execute procedure.
- **Editor commands** are C#. **Game commands** are described by the DLL and run in the game through `Game_API.editor_poll`. A game command that changes the scene returns operations, and the editor applies them as for any edit, so they can be undone.
- **Menus are data.** A menu of commands is a list of entries (`MenuEntry` in `Cinnabar.Editor.Commands`): a command by its ID, a separator, or a menu under a label with entries of its own. A command's ID converts to its entry, so a list of IDs is a menu. The ribbon's split buttons and dropdowns have such menus, and so has the Add menu, wherever it shows (see [Add](#add)). `MenuEntry.Validate` finds a command that the registry does not have, and a menu under a label with nothing in it.
- **Screenshot** (F12) and **Record Last 5 s** (Shift+F12), in the Window tab's Capture group, ask the host for a PNG of the next frame or a GIF of the last five seconds, and write a sidecar of the editor's state beside it (see [Capture](capture.md#capture)). They need a linked host, and one capture runs at a time.

### Game commands

- **The game registers them** with `editor.register_command`: an ID, a label, a description, the ribbon tab and group by label, an icon of the editor's set, whether it edits the scene, and a procedure. The strings and the procedure are the DLL's, so the commands are registrations: `editor.reload` forgets them, and the game registers them again in `on_reload`, as it does its systems.
- **The editor gets the list** as `Game_Commands`, with the component types, when it links and after a code reload. It registers each as `game.<id>`, removes the ones that the list no longer has, and adds each to its group at the end of the tab with that label, such as Gameplay, or of a new tab after the others. A group of one or two commands has large buttons, and a larger one stacks of small buttons. The commands are in the command palette too. A command that edits runs only in Edit, and every command needs a linked host.
- **Running one** sends `Run_Game_Command`. The game calls the procedure in `poll`, between frames, with a `Command_Context`: the world, the scripts, the game's own data that it passes to `poll`, the editor's selection and camera. The procedure does not change the scene itself: it adds operations by scene ID to the context, which `editor.new_scene_id`, `scene_numbers`, `scene_position` and `scene_field` help build, and it can set a message. The game sends them back in `Game_Command_Result`. The editor turns the wire operations back into the document's, applies them as one undo entry under the command's label, which sends them to the game as for any edit, writes the message to the console, and selects the entities that the command created.
- **The sample's commands** are on the Game tab: Add Triangle makes a spinning triangle 2 m in front of the editor's camera, Reverse Spin negates the selected triangles' speed, and World Report writes the counts to the console without an edit.
- **Toggles and choices:** a command with a checked state is a toggle. A choice command picks one of a list of options. A command raises `Changed` when it runs, and owners of shared state, such as the host session, invalidate every command, so views update without polling.
- **Key bindings:** `keybindings.json` in the editor settings is an object from command ID to key gesture, such as `{ "view.stats": "F3" }`. An empty gesture removes a shortcut. When two commands get the same gesture, the first by ID keeps it, and the console says so.
- **The command palette** (Ctrl+Shift+P) searches every command by label and ID. Every word of the query must match. A label that starts with the query ranks first, then a label with a word that starts with it. The box beside the ribbon's tabs opens it. The ribbon shows a command only on its tab, and the palette finds it from anywhere.

### Add

The editor adds an entity of a common kind in one step (`EntityCatalog` in `Cinnabar.Editor.Document`, `EditorShell.AddEntity`).

- **A kind** has a label, a category, an icon, a description, and the components that the entity starts with. A component has the fields that make the entity useful at once, and no more. A light that is added as a component alone has an intensity of 0, and shows nothing. A point light of the catalog has an intensity, and casts shadows.
- **A kind can start turned.** A light that shines along its +z, such as the spot light, starts turned down. The directional light starts at an afternoon angle, 50° down and 30° round, so that walls along the axes have a lit side and a shaded side.
- **The kinds:**

  | Category | Kinds |
  |---|---|
  | No category | Empty Entity, which has a `Transform` alone |
  | Lighting | Directional Light, Point Light, Spot Light, Quad Light, Disk Light, Line Light, Reflection Probe |
  | Rendering | Camera, Mesh, Sprite, Particle System |
  | Volumes | Global Volume, Box Volume and Sphere Volume. Post-Processing Volume, a global volume with an `Exposure`, a `Tone_Mapping` and a `Bloom`. Fog Volume, a box volume with a `Fog`. |
  | Physics | Static Collider. Rigid Body, with a `Collider`. Trigger, a `Collider` that is a sensor. Character. |
  | Audio | Audio Source, Audio Listener |
  | Navigation and AI | Navigation Volume, a box volume with a `Nav_Mesh_Volume`. Agent, with a `Character`, a `Nav_Agent` and an `Agent`. |
  | UI | UI Document |

  A project's own kinds are its prefabs, which the content browser places (see [Prefabs](prefabs.md#panels-and-the-viewport)).
- **Each kind is a command,** `entity.add.<id>`, such as `entity.add.pointLight`, so the command palette and a key binding can run it. Three kinds have other IDs: the empty entity is `entity.create` (Ctrl+Shift+N), the global volume `entity.createVolume`, and the reflection probe `entity.createReflectionProbe`. The commands need an open scene and the Edit mode.
- **The Add menu** (`DefaultRibbon.AddMenu`) has the empty entity first, then a menu for each category, in the catalog's order. It is in four places: the Home tab's Add group, the button beside the outliner's filter, the bottom of the Scene's tool strip (see [Viewport](viewport.md#tool-strip)), and Add Here in the menu of an outliner's row. The Lighting, Environment, Gameplay and Audio tabs have the kinds of their work as buttons.
- **Where the entity goes:** where the selected entity is, or the primary one of several, so that a drag of the gizmo tells the two apart. Without a selection, it goes to the pivot of the active scene view, which is in view, if that view is shown. Otherwise, it goes to the origin. Add Here first selects its row, if the row is not in the selection, so the new entity goes where the row's entity is. In a prefab that is open, the entity goes under the root, and keeps its place in the world (see [Prefabs](prefabs.md#editing-a-prefab)).
- **One undo entry** makes the entity, as a root with the kind's label as its name. The entry is Add and the label, such as Add Point Light. For the empty entity, the entry is Create Entity and the name is Entity. The editor then selects the new entity.

### Value boxes

Every box in the panels and the asset editors that edits a value commits in the same way (`CommitBox`, in `Panels/CommitBox.cs`):

- **Commit and put back:** Enter, or Ctrl+Enter in a box of lines, and the loss of focus commit the text. Escape puts the value back. A list of completions that is open keeps Enter and Escape for itself.
- **Once for each text:** a box does not commit again the text that it last committed, or the value that it shows. So Enter and then the loss of focus make one undo entry. A commit that builds the panel again takes the focus from the box inside the commit, and that loss commits nothing.
- **Formats:** a box reads its text through a format, `IValueFormat<T>`, which also writes a value as text. `ValueFormats` has text, a number and a whole number with a range, a material's or an animation graph's numbers, a cutscene's ticks, and an optional value, which is null for an empty box. Numbers are read in the invariant culture, as the files write them.
- **Refusals:** a text that does not parse, a number outside the range that the setter takes, or a value that the setter refuses, such as a name that another has, is not set. The box puts the value back and shows the problem as its tip until the next commit or Escape. The panel does not build again for it, and the box writes nothing to the console. A setter that says why itself still does, as a field of the properties panel and the UI editor's id and style name do.
- **Whose value:** in the properties panel, the value is the host's, and the box keeps what the user types while the host's values arrive. A box over a value that other controls change too, such as the UI editor's custom screen size, which its presets set, reads the editor's value, and shows it again when it shows again. Elsewhere, the value is what the box started with, and then each text that it committed, since the panel builds again when its document changes.

### Details panels

The details of the material, animation graph, decision, UI and cutscene editors show the selected node, element or block as rows. Each is a `DetailsPanel` (in `Panels/DetailsPanel.cs`), which builds its rows in one way:

- **Built when what they show changes:** each panel has a key of what its rows depend on, such as the node's fields and its problems. The panel builds the rows again only when the key changes, so a box keeps its focus while a drag moves its node. A change that the key does not have, such as a cook that renames a material function, builds the rows again anyway.
- **Held during a drag:** the UI editor holds its rows while a drag or a picker's session is open, and the cutscene editor holds a block's rows while a drag edits it. The rows build when the drag ends.
- **One build at a time:** a build never starts inside another (`RebuildGate`), as in the properties panel. A problem from the cook daemon can arrive while the user types in a box. The build that it starts clears the rows, which takes the focus from the box, so the box commits its text. The build that the commit asks for runs after the first one ends, and the rows are built once.
- **Problems:** every panel, and the asset editors' other panels, show a problem in one way (`Kit.ProblemText`): an error or a warning colour, after its line where the panel shows it. In the content browser, a click on a problem opens its file.

### Outliner

- The outliner is a virtualized list of the visible rows of the tree, indented by depth. A tree control with one item per entity does not scale to tens of thousands of entities.
- The hierarchy comes from `Parent`, in handle order. An entity whose parent the editor does not know is a root.
- **Several scenes:** with more than one scene open, each scene's entities are under a heading of their own, and what no open scene made, as the game's own entities, comes last. A click on a heading makes its scene the active one, and its menu makes it active, saves it or closes it (see [Several scenes](document-and-scenes.md#several-scenes)).
- **Collapsed rows:** rows start expanded, and the shell keeps the ones that the user collapsed (`OutlinerState`), so a view that docking rebuilds has them. A scene entity is kept by its scene's number and its scene ID, so its row stays collapsed after Stop or a resync, which give every entity a new handle. A scene's heading collapses too. An entity that the game spawned is kept by its handle, so its row is expanded again after a resync.
- A row shows the entity's name, or the entity as the engine prints it (`Entity(3:1)`) when it has none, and its components, without the ones that the tree shows itself (`Parent`, `Previous_Transform`, `Inactive`, `Disabled`, `Name`, `Scene_Entity`). An inactive entity is dimmed.
- **Icons:** a row has an icon for what its entity is, by its most telling component (`EntityIcons`). The components are in an order that puts what a person looks for first: a camera, the lights, a reflection probe, the volumes, a UI document, an agent, a character, a particle system, an audio source, the renderers, the bodies and colliders, an audio listener, and then `Behaviours`. A guard with a mesh, a character and an agent has the agent's icon, and a camera with a listener has the camera's. An entity with none of these components has no icon.
- **Selecting:** a click without Ctrl or Shift selects that row alone. With Ctrl or Shift, the rows that the click adds come last, so the row clicked is the primary entity. The selected entities that have no row, which a filter or a collapsed parent hides, then stay selected.
- **Filter:** a filter shows the rows whose name, entity or components match, with their ancestors. The box beside it shows one sublevel, or the base, by the same rule, and the shell keeps its choice (`OutlinerState.Sublevel`). The button beside them opens the Add menu (see [Add](#add)).
- **Sublevels:** a root that is in a sublevel has the sublevel's name as a tag. Its descendants are in it too, so they have none. The entities of a sublevel that the game's world does not have, because Edit does not load it or the active set lacks it in Play, stay in the outliner from the document, dimmed, after their scene's other rows (`OutlinerDocumentRow`). They have no handle, so they cannot be selected, and the viewport cannot pick them. Their menu has Load, which loads the sublevel in Edit.
- **Dragging** a row onto another row reparents its entity, and onto the space below the rows makes it a root, without moving it in the world. A row cannot go under itself or its descendants, or under an entity of another scene: the drop is refused and the console says why (see [Several scenes](document-and-scenes.md#several-scenes)). A row also drags onto an entity field in the properties panel.
- Double-clicking a row, or Focus in its menu, frames its entity in the viewport, as F does.
- **A row's menu** has Focus, Duplicate, Delete, Add Here, Move to Root, Sublevel, which puts the selection in the base or a sublevel and checks the row's own (see [Sublevels](#sublevels)), the prefab commands (see [Prefabs](prefabs.md#panels-and-the-viewport)), Hide or Show, and Lock or Unlock. It acts on the selection when its row is in it, and on its row alone otherwise. Add Here has the Add menu, and the new entity goes where the row's entity is (see [Add](#add)).
- A row whose entity the game could not apply all of has a warning mark, with the problems in its tooltip.
- **Visibility and lock are editor state.** Each row of a scene entity has an eye that hides it in the viewport and a lock that stops the viewport from picking it, and each applies to the entity's descendants too. A hidden row is dimmed, and a toggle that is on is bright. Hide (H in the viewport) and Lock act on the selection, from the Home tab's Visibility group or a row's menu, and Show All, in the same group, shows every hidden entity. Neither changes the game's `Disabled` state, and neither is saved in the scene: the editor keeps them by scene ID for each user and each scene file, in `scene-views.json` in the editor's settings.
- **Hidden entities are not drawn.** The editor sends their handles in `Set_Hidden` when they change, when their handles change, and after each snapshot. `editor.draw_frame` adds the hidden entities with their descendants to `Frame_Desc.hidden`, and the renderer and a game's own geometry (`render.is_hidden`, from `Frame.hidden`) leave them out, so they are neither drawn nor picked, and they cast no shadow in the sample. A locked entity is drawn and picked, and the editor drops it from the pick's result. The outliner still selects both.

### Properties

- The panel is built from the type descriptors: one group per component or behaviour, one row per field, and an editor for each field kind. A component with no fields the editor can show, such as a tag, is a chip with its name. The components that the header shows (`Parent`, `Name`, `Inactive`, `Scene_Entity`) and `Behaviours` are not groups.
- **Editing:** a field edits when the document has its component or behaviour. A number, a string or an axis is a box that sets the field on Enter or when it loses focus, and puts the value back on Escape. A box commits a text once: Enter and then the loss of focus make one undo entry. Dragging a number's name, or an axis's colored marker, changes it in one undo entry, ten times as fast with Shift and a tenth with Ctrl. A number with a range also has a slider, whose drag is one undo entry, whether the press is on the thumb or on the track. The range is only the slider's: a typed value can go beyond it. A color has a swatch and its red, green and blue boxes. Clicking the swatch opens a picker of hue, saturation and value in sRGB, and a hex box, which edit the color in one undo entry while it is open. A color brighter than white keeps its brightness: the picker edits the color scaled to at most 1. All zero, which is the default color, shows hatched. A `bool` is a check box, an enum a choice of its names, and an entity reference takes a drop from the outliner and has a button that clears it. A rotation edits as Euler angles, so an edit of one angle keeps the others as they show. A position edits in meters, with m, km, Mm or Gm, and the other axes keep their raw values exactly. A box that has focus keeps what the user types while the host's values arrive.
- **What does not edit:** fields with `editor:"read"`, a child's `Transform`, which propagation writes from its `Local_Transform`, `Previous_Transform`, which the world writes, and entities that the game spawned.
- **The header** edits the name and, with the Active badge, the active state. The name's box commits a text once, as a field's box does. Each group has a button that removes its component or behaviour.
- **Add Component** is one button at the bottom of the panel, for an entity that the document has. It opens a picker of what the entity can gain (`CatalogPicker`): a search box, and under it folders, which are closed until clicked. A folder that the user opened stays open across selections.
  - **Component types** are those that the game registers and the entity lacks, each in the folder that it registers in (the `category` of `ecs.register_component`, see [World: ECS](../world/ecs.md#component-registry)). The engine's folders are Lighting, Rendering, Volumes and Volumes/Settings, Physics and Physics/Joints, Audio, Animation, UI, Navigation, AI and Transform. A game's own type is in a folder named for its package, as the sample's `Spin` is in Mygame, unless it gives a category. A type with `ecs.NO_CATEGORY` (`"-"`), which the engine adds and removes itself, such as `Physics_Body`, is not offered. A `Transform` or a `Local_Transform` that the picker adds starts as the identity.
  - **Behaviours** are the scripts that define a behaviour and that the entity lacks, from the cook daemon's index. A class that names a `category` in `Behaviour.define` is in that folder, such as Tools/Layout, and one with `"-"` is not offered ([Scripting](../scripting/behaviours.md#behaviours)). The others are under Behaviours, in the folder of their script. A first folder named `scripts` is left out, so `scripts/ai/guard.luau` is in Behaviours/Ai, and `scripts/door.luau` in Behaviours. While the index has no content roots, as before the cook daemon runs, the picker says under its rows that the scripts are not listed yet. A script that defines a behaviour also drags from the content browser onto the panel.
  - **Search:** typing shows the items whose label or folder has every word of the query, ranked as the command palette ranks them, each with its folder beside it. The best match is selected, so Enter adds it. The arrows move through the rows, a click adds an item or opens a folder, and Escape closes the picker.
- A component that the document has and the game does not is a group with its values as the file writes them. The scene keeps it, and the group can remove it.
- The panel builds its controls when the entity, its components or its behaviours change. When only values change, it updates their text, so it keeps its expanders and scroll position while values change twenty times a second. A collapsed group stays collapsed across selections. A build never starts inside another (`RebuildGate`). Clearing the rows makes a focused box lose the focus and commit its text, and that edit asks for a build. Such a build waits, and runs once when the build under way ends.
- An entity reference, such as `Parent` or an entity field, is a link that selects that entity.
- **Reset:** a field that the scene sets shows a reset button, which removes it from the scene. With prefabs, the default is the prefab's value.
- **Keys:** while a cutscene holds the preview, a field of an entity that it binds has a key button, which keys the field at the playhead, and its right-click menu adds, keys, removes and finds its track (see [Cutscene editor: Keying](cutscene-editor.md#keying)). An entity that no binding possesses has an empty button that asks to possess it, and several selected entities share one button. A field that the preview holds shows what the world shows, and its edits go to the cutscene, as preview values or with auto-key as keys, never to the scene (see [Cutscene editor: Where an edit goes](cutscene-editor.md#where-an-edit-goes)).
- **Cameras:** a `Cinematic_Camera`'s group ends with a **Sensor** choice of presets (full frame, Super 35, Super 16 and IMAX 70 mm), which sets the sensor's width and height in one edit, and with its lens in words (`CinematicCameraText`): the field of view that the focal length gives on the sensor, the sensor's aspect, then the aperture and the focus, or that it has no depth of field (see [Depth of field](../rendering/post-processing.md#depth-of-field)). A `Camera` beside one notes that the lens sets its vertical field of view.
- **Reflection probes:** a `Reflection_Probe`'s group ends with the probe's state, from the game's `Reflection_Probe_View` (see [Viewport](viewport.md#reflection-probes)), and a Capture button, which captures the selected probes now:
  - **No slot** when probes of a higher priority or nearer the camera hold every slot, so the probe has no capture;
  - **waiting** when it holds a slot but has no capture yet;
  - **captured at** the clock time of its last capture, and **provisional** when the level was still loading then, so it captures again once the level is in;
  - **capturing now** while its capture is in flight or asked for.

  Without a linked game, or with the game's reflections off, it says so. The state updates in place when the game sends it, which is when it changes, so it does not rebuild the panel.
- **Volume settings:** a volume's setting has a check box before its name, ticked when the volume overrides it (see [World](../world/volumes.md#volumes)). A new volume's settings show their defaults, unticked and dim. Ticking a setting overrides it with the value that shows, and changing the value ticks it. Clearing the check box keeps the value, as `<field>.override = false` in the scene, so ticking it again brings it back, which compares the volume's value with what is below it. The reset button sets the setting back to its default, unticked.
- **Multi-select:** the panel shows the components that every selected entity has, without the behaviours. A field whose values differ shows "—", and setting it, dragging it or resetting it makes one operation for each entity, in one undo entry; an axis edit keeps each entity's own other axes. Removing a component removes it from each, and the Active badge sets all. Add Component opens the same picker with component types only, those that some selected entity lacks, and adds the chosen type to each entity that lacks it. The fields edit only when the document has every selected entity.
- **How values show:** vectors, positions and rotations are three boxes marked red, green and blue for x, y and z. A rotation shows Euler angles in degrees, in the engine's order (z, then x, then y, as `Quaternion.euler` in scripts), with the quaternion in the tooltip. A position shows a distance in the largest unit of m, km, Mm and Gm that keeps it short, with the exact meters in the tooltip, and sets raw values. Numbers have grouped thousands and at most three decimals. A `bool` is a check box, an enum its value's name, and names read as words: `Previous_Transform` is "Previous Transform". Components without fields, such as tags, are chips under the groups, and a behaviour's group has a Script badge, which says Edit Mode too for a class that runs in the editor's Edit mode.
- An entity reference shows the target's name, and accepts a drag from the outliner, also of an entity of another open scene. A reference to a scene that is not open shows "Not open: {file}", or "Missing scene" when the content has no such scene, with `@<guid>/<id>` in the tooltip, and `×` clears it. A reference to an entity of a sublevel that the game's world does not have shows "Sublevel not loaded: {name}", with the reference in the tooltip (`FieldEditor.Unavailable`). An asset reference (see [Rendering](../rendering/assets.md#asset-fields)) shows the asset's name, or its name in its file for a sub-asset such as a mesh; a click on the name shows the asset in the content browser. With the `…` button it picks from the assets of the field's kind, it accepts a drag from the content browser of an asset of that kind only, and `×` clears it. An asset that is not in the content shows as missing, with its GUID in the tooltip. A field can also take built-in values, which are not assets: each shows as itself, and the picker offers them first. The asset pickers of the material, animation graph and UI editors are this view too, over their documents' values (`ValueSink`), so they show a missing asset the same way and take a drop from the content browser.

### Sublevels

The Sublevels panel (`SublevelsView`, `EditorShell.Sublevels.cs`) shows the project's sublevels and puts entities in them (see [World: Sublevels](../world/sublevels.md#the-active-set) and [Parts](document-and-scenes.md#parts)).

- **Rows:** the base first, then each sublevel that the project declares, in the order of its files, then each sublevel that entities of the open scenes are in and the project does not declare. Such a row is marked "not declared" and has a Declare button, because its scene does not cook. Each row has how many entities of the open scenes it has, descendants included.
- **Starts active** writes `sublevel.<name> = active` or `= inactive` in `project.settings`. A text box under the rows declares a new sublevel, inactive, and `×` removes a declaration. A declaration that entities of the open scenes use stays, and the console says why. A name has 1 to 31 letters, digits and underscores, and a project has at most 32 sublevels. The panel shows what the project file and the user file declare together, and writes the project file.
- **Load in Edit** loads or unloads the sublevel's parts of every open scene (`EditorShell.SetSublevelLoaded`). Each part goes alone, and the other parts' entities keep their handles. Every sublevel loads until the user unloads it. The choice is each user's, for each project: `sublevels.json` in the editor's settings lists the sublevels that Edit does not load, by the project file's path. It is not in `project.user.settings`, because the game reads that file.
- **Play** starts with the project's active set, not the editor's choice, so Play is what the game does. Before the game plays, the parts of each sublevel whose choice and active state differ load or unload. Stop sends the scenes again, with the editor's choice. A change of Starts Active during Play applies at the next Play, as the game's applies at the next level. Outside Edit, the Load in Edit check boxes are disabled.
- **Assign** puts the selected entities of the open scenes in the row's sublevel, or in the base, with their descendants (`EditorShell.AssignSublevel`). It makes one undo entry in each scene that it changes, such as Move Crate to night. A child is in its parent's sublevel, so a selected child whose parent is not selected stays where it is, and the console says why. The Sublevel menu of an outliner's row does the same.
- **Commands:** `sublevel.assign.base` and `sublevel.assign.<name>` assign the selection, and `sublevel.load.<name>` loads or unloads a sublevel in Edit, for the command palette. They follow the project's declarations.

### Face

- The Face panel is mesh mode's face edit sheet (see [Mesh editing](mesh-editing.md#mesh-mode)): with faces selected, their material, with the properties panel's asset picker and drop target, the dev materials first; the material's tool texture and its size; the faces' texel density beside the scale, and the project's; the mapping's axes, read-only; its scale, shift and rotation, typed or dragged as the properties panel's numbers are, each drag one undo entry; the hotspot the faces sit on, in the warning color when the texture leaves it; and the texture tools as buttons. A field whose values differ among the faces shows a dash, and an edit sets every face.

### Atmosphere

The Lighting tab's Atmosphere, Sun, Sky and Weather groups and the Atmosphere panel edit the scene's surroundings, whatever is selected (see [Rendering](../rendering/sky.md#sky)). The groups turn the atmosphere's parts on and off and apply presets, and the panel has every setting.

- **The atmosphere's volume** is a global volume of the scene's: one with an `Environment`, the highest priority first (`Atmosphere.Find`). Every edit of the groups or the panel is one undo entry, and when the scene has no such volume, the same entry first adds a global volume named Atmosphere at the origin, with an `Environment` in Atmosphere mode linked to the scene's first directional light, or gives a global volume without one an `Environment`. Setting a setting overrides it, as the properties panel's edits do.
- **The Atmosphere, Sun and Sky groups:** in the Atmosphere group, Atmosphere selects the volume, and Sky picks Flat, Atmosphere or Texture. In the Sun group, Link Sun links the sky's sun to the selected directional light, or the scene's first, and unlinks it when it is linked. Time of Day aims the sun at dawn, morning, noon, afternoon, dusk or night: a linked sun turns its light, and the sky's own sun sets its azimuth and elevation. In the Sky group, Air resets the atmosphere's air and sets clear, hazy, dusty or alien air, and Stars and Moon show or hide the night's. Aim Sun at Sky, with a Texture sky, asks the game where the texture's sun is (`Sky_Sun_Request`) and aims the sun there as Time of Day does, as one undo entry, so it can be moved on from there; the console says where, or why the sky has no sun: it is not a texture's, the texture is not ready yet, or nothing in it stands out. The panel's sun group has it as a button in Texture.
- **The Weather group** has the fog and the clouds (see [Rendering](../rendering/clouds.md#clouds)). Fog adds the volume's `Fog`, or sets its density to 0 and keeps its other settings, and Fog Density sets a fog's density and falloff. Clouds adds the volume's `Clouds` with a density of 1, or sets its density to 0 and keeps its other settings, as Fog does. Weather sets the clouds' coverage, precipitation, type, cirrus and thickness to Clear, Scattered, Overcast or Storm, after resetting those five, gives the volume a `Clouds` with a density of 1 when it has no clouds, and takes the weather from the scalars; the weather map stays, for when the source goes back to it.
- **The weather's source and Center Weather Here** are in the panel's clouds group, and are commands for the command palette. The source picks Scalars, the same weather everywhere, or Map, the weather map. Center Weather Here puts the map's origin under the editor's camera, in raw units as a `Transform`'s position is.
- **The Panels group** shows the Atmosphere panel and the [Weather map](#weather-map) panel.
- **The panel** has groups for the sun, the sky, the night, the fog and the clouds, with the properties panel's rows: sliders, colors, override check boxes and reset buttons (`FieldGrid`). The sun's group has its link, its azimuth and elevation, which turn a linked light's rotation, or its `Local_Transform`'s under a parent, so its world rotation is the one asked for; then the linked light's color and intensity, or the sky's own sun's illuminance; and the disc's size. The sky's group has Flat's colors, the atmosphere's air, or the texture, its intensity and its rotation with Flat's colors, which show until the texture is ready, by the mode, and the night's group shows only in Atmosphere. The clouds' group, once the volume has a `Clouds`, has the density and the weather's source; then by the source, either the coverage, the precipitation, the type and the cirrus, or the weather map, its origin and its size in meters, the cirrus and a Center Weather Here button, with a dim warning under a map that is not a data texture, since the clouds read its channels raw; then the wind, the heights, the base variation and the far clouds, labelled with their units, and a Weather Map… button that shows the panel. Without a `Clouds`, it has Add Clouds. A drag of a name or a slider is one undo entry.
- **Values:** the panel watches the volume and the linked light while it shows them, as the properties panel watches the selection (`EditorShell.Watch`), so they have values whatever is selected. The shell counts the watches, so a change of the selection does not stop them.

### Weather map

The Weather Map panel paints the clouds' weather map (see [Rendering](../rendering/clouds.md#weather)), the texture whose red, green and blue are the coverage, the precipitation and the cloud type over the volume's `weather_size` meters around its `weather_origin`.

- **The map** is the atmosphere volume's `weather_map`, read from its file in the content root as a `WeatherMap` in `Cinnabar.Editor.Document`: the texels as RGBA bytes, which paint, generate, and read and write a PNG themselves, so the editor needs no image library for the asset. The panel reads a PNG with the editor's own decoder, and one it does not read, with a palette, 16-bit texels or interlacing, through Avalonia's. The controls are over the map, and scroll. While a map shows, they take at most half of the panel's height, and the image fills the rest, its channels as colors. Without a map, the panel has the controls alone, since there is nothing to paint. The New Weather Map section is open while the volume has no map and closes when it has one, so that the brush is over the map; between those changes it stays as the user leaves it. The map, where its file is and the strokes since it was read are the shell's `WeatherMapSession`, as one `MapState` that holds the map, its history and the stroke under way inside the states that have a map: none, when the volume names no map; unknown, when the index does not list the map; written, when the editor wrote the file and the index does not list it yet; indexed; or unreadable, with the reason. Every change goes through one method that sets the state and tells the panel. The panel says which over the map.
- **Strokes are asset writes, not undo entries.** The brush paints one channel, Coverage, Precipitation or Type, toward its value, or toward 0 with Shift, with a radius in texels, a strength and a hardness. A stroke edits the map as the pointer moves and, when it ends, writes the PNG through a temporary file; the daemon cooks it and the host streams the texture again, so the clouds follow in a few hundred milliseconds. Nothing goes on the scene's undo stack, as for every asset operation. The panel keeps the map before each of the last 32 strokes: Ctrl+Z, while the panel has the focus, and Undo Stroke put the last one back and write the file again, and Revert to Saved reads the file again and drops the history. The history is the shell's, so a panel that docking rebuilds keeps it, and a new map starts it anew.
- **New Weather Map** fills the map from noise, the same for the same seed: a tiling Perlin fbm of the scale's cells across the map for the coverage, and tiling Worley cells for the precipitation and the type, so a few cells rain and lean toward cumulonimbus, with a bias from -1 to 1 added to each channel; the scale is 1 to 64 cells and the octaves 1 to 8, and their boxes refuse a value outside that range; the size is 256, 512 or 1024. On a volume with a map, Generate writes over its file, with the map before it in the stroke history. On a volume whose map cannot be read, Generate writes over the file if it is a PNG, with no history, and otherwise logs an error and leaves it, since it is the volume's map all the same. On a volume without a map, Generate refuses while the game plays, before it writes anything, and otherwise it writes `<content root>/textures/<scene stem>_weather.png` under the content root that the scene is in, with its `.meta` file first, as a new mesh's is written (see [Content pipeline](../content/daemon-and-operations.md#asset-operations)): the GUID, `usage = data` and `[mip_map] enabled = false`, which the cooker reads as the clouds do, raw at the first level. Then, as one undo entry, it names the map in the volume's `weather_map`, takes the weather from the map, and puts `weather_origin` under the editor's camera unless the volume sets one. Undoing that entry keeps the file, and redoing it reads the file again. The session keeps the written path until the index lists the GUID, and says that the content daemon is not linked when it is not, since the map is not cooked until it is.

### Resource monitor

- **The host** sends `Host_Stats` four times a second while the editor is linked: the frames of the interval with their average and longest frame times, and how much of each the game's update and the frame's end took; the permanent arena's size and the most that a frame's arena used; and from the GPU backend's `stats`, the live buffers, textures, samplers, pipelines and acceleration structures, the most that a frame's upload ring used, and the adapter's local memory in use against the budget that the OS gives the process. It sends the memory of the backend's resource heaps and the part of it that the resources take, which the panel shows as `Resource heaps` while there is a heap (see [GPU](../gpu/resources-and-pipelines.md#memory)). It also sends the bottom-level acceleration structures' memory, and their memory before compaction (see [Ray scene](../rendering/ray-scene.md#acceleration-structure)). The panel shows that row only while a structure lives, with the memory before compaction in parentheses after a compaction.
- **The game** sends `Game_Stats` as often: the entities, the archetypes, the behaviour instances, the script VM's bytes, and each loaded module's part of them (see [Scripting](../scripting/embedding.md#embedding)). It also sends the camera's draws and instances, drawn and hidden by occlusion culling (see [GPU scene](../rendering/gpu-scene.md#occlusion-culling)). The panel shows the draws and instances with the late ones in parentheses. It sends the meshlets that the walk of the meshlets' hierarchy selected, and all the meshlets of the items that it walked (see [GPU scene](../rendering/gpu-scene.md#mesh-shader-path)), which the panel shows as `Meshlets tested`. With the [split cascades](../rendering/global-illumination.md#split-cascades), it sends each cascade's probes that rays reached, its slots and the keys that found no room, which the panel shows as `GI cascade k probes`. With the viewport's Shading Stats, it sends the forward pass's 2x2 quads and the pixels that they cover (see [Rendering](../rendering/lighting-and-shadows.md#quad-overdraw)), which the panel shows as `Forward quads`, with the share of their lanes that cover a pixel. With a [virtual shadow map](../rendering/lighting-and-shadows.md#virtual-shadow-maps), it sends the pages requested, allocated and missed, the pages that the pool held, that drew and that left the pool for them (see [Caching](../rendering/lighting-and-shadows.md#caching)), and the pages that the pool holds and its capacity, which the panel shows as `Shadow pages requested`, `Shadow pages allocated`, `Shadow pages missed`, `Shadow pages cached`, `Shadow pages drawn`, `Shadow pages evicted` and `Shadow page pool`, with the pool's fill. It also sends the pages that [streaming](../rendering/lighting-and-shadows.md#streaming) dropped in the last frame and those that wait for their turn, which the panel shows as `Shadow pages streamed`, with the waiting pages when there are any, and the pages that the pool held that the casters that changed made invalid, with the levels that dropped every page past the cap (see [Caching](../rendering/lighting-and-shadows.md#caching)), which the panel shows as `Shadow pages invalidated`, with the whole levels when there are any. With the shadow atlas's [cache](../rendering/lighting-and-shadows.md#cached-shadow-maps) holding a light, it sends the lights that the cache holds, the slots that the frame copied from it and those that it drew into it, with those that a dynamic caster's report drew, which the panel shows as `Cached shadow lights`, `Shadow slots copied` and `Shadow slots drawn`. With the [reflection probes](../rendering/lighting-and-shadows.md#reflection-probes), it sends the probes in the frame, the slots whose probe has a cube, the level's slots and the faces that the frame captured, which the panel shows as `Reflection probes`, `Reflection probe slots` and `Reflection probe faces`. With any reflections, it sends the bytes that they keep between frames, the probes' cubes and the screen-space or traced reflections' histories (`render.reflection_memory`), which the panel shows as `Reflection memory`. With a paged mesh resident, it sends the pool of [mesh pages](../rendering/assets.md#mesh-pages): the pages that are resident and the pool's slots, the pages that views want and that are not resident yet, and the bytes a second that the frames copy in, which the panel shows as `Mesh pages resident`, with the pool's fill, `Mesh page pool`, in bytes, `Mesh pages pending` and `Mesh pages streamed`.
- **The game** also sends the pushes of the input contexts, the top first, each with its context, its pusher and its pads (see [Input: Contexts](../core/input.md#contexts)).
- **The panel** shows a minute of frame times as a graph, with lines at 16.7 ms and 33.3 ms; the host's memory and resources; the world; the modules by memory, the largest first; and the input contexts, the top first, with `default` under them. It keeps a minute of samples, and forgets them when the link closes.
- **The graph's lines:** the longest frame of each interval, faint, and from the profiler's summary, which comes with each `Host_Stats`, the average CPU time in red, GPU time in teal and wait in amber ([Core](../core/profiling.md#frames-and-costs)). The pointer shows an interval's times. **A click** captures the interval's longest CPU frame in the profiler, or its longest GPU frame when the pointer is nearer the GPU line.

### Profiler

The profiler panel shows where a frame's time goes, from the host's profiler ([Core](../core/profiling.md#profiler)). It keeps its state in the shell's `ProfilerModel`, so a panel that docking rebuilds shows the same capture.

- **A capture** is one frame. **Capture Frame** (Ctrl+Alt+P) takes the next frame, **Capture Worst Frame** the longest of the recent frames (120 from the ribbon, or 30, 60 or 120 from the panel), and a click on the Resource Monitor's graph a frame of that interval. The host answers once the frame's GPU times are in, a few frames later. It keeps the last 128 frames and the worst frames of the last minute's intervals, and a frame that it no longer has is unavailable, with the reason.
- **The timeline** has a lane for each thread that ran in the frame, the main thread first, with its zones in rows by depth, and a lane for each GPU queue with its passes. Each thread's lane says how busy it was. Solid lines mark the frame's start and end, and dashed teal lines the GPU's first and last timestamps. Zones are colored by category and labeled where they fit. Zones too narrow to see merge into one dim block. A zone that its fiber suspended in is cut, with a bright edge where it stopped and where it went on, maybe on another lane, and hovering one outlines all its segments. Job zones are grey.
- **Navigation:** the timeline's view is `TimelineView` in nanoseconds. The cutscene editor's timeline shares it, in ticks (see [Cutscene editor: The timeline](cutscene-editor.md#the-timeline)). The wheel zooms around the pointer, Shift and the wheel scroll the lanes, a drag or a middle drag pans, a click selects a zone, a double click zooms to it, F or Fit fits the frame, and Escape clears the selection. The pointer's tooltip and the strip under the timeline give a zone's name, callback, time, self time without its nested zones, start, lane and category, and how many times its name ran in the frame.
- **The cost tables** are the last stats interval's costs per frame: **GPU passes** by queue, **Systems**, and **Scripts** by class and callback. Each has the calls, the average and the most in one frame, and the share of the frame's CPU time, or GPU time for passes. A header sorts by its column, and again turns the order around. Selecting a row highlights its name in the timeline.
- **Record** turns the host's recording of zones on or off. Off, captures have no zones and the tables empty. The host records again when the editor disconnects.
- The status line shows the capture's times and the zones that the host dropped, which a thread that records more than its ring holds in one frame loses.

### Content browser

- **The index is the daemon's.** `AssetIndex` in `Cinnabar.Editor.Content` mirrors the daemon's `Asset_Snapshot` and `Asset_Delta` events, as `WorldModel` mirrors the game's world. The editor never scans the content roots itself.
- **The model keeps what the browser shows.** `ContentBrowserModel` in `Cinnabar.Editor.Content` has where the browser is, the filter, the selection and the view's shape, so they last when docking rebuilds the view, and the asset commands have a folder and a selection whether the panel shows or not. Each user's grid or list and tile size are in `content-view.json` in the editor's settings. Where the browser is is one `ContentLocation`: a folder, a file of it, or a prefab with the entity whose children show. One method moves it, and a file or prefab's folder is where the asset is, so when the open file moves, the path over the assets and the folder that new assets go to move with it.
- **Layout:** the roots and their folders on the left, as a virtualized list of the visible rows like the outliner's, the assets in the middle, with the path over them, each part a link, and the details of the asset that was selected first on the right. The panel docks at the bottom, where it is wide and short, so the details are a column. Roots start expanded. Over the assets, the daemon's state, its progress while a pass cooks, such as "Cooking sponza.usdz 412/1088" or "Cooking textures 12/340", or its last cook: what it cooked, in how long, and how many assets failed. Problems that belong to no asset, such as a broken definition file, show over the panel.
- **Pop-out:** Pop Out, over the assets or in the command palette, puts the panel in a window of its own, 1100 by 700, for a second monitor, and Dock puts it back. It shows the same model, so its folder, filter and selection stay. Closing that window docks the panel again. The window has the shell's shortcuts, because a window's key bindings are its own, and assets drag from it onto the main window's panels. It closes with the editor. A saved layout keeps its place and size, and it opens there again, on the first screen if the monitor that it was on has gone.
- **Grid and list:** the assets are tiles, with a size from a slider, or a list. A tile shows the asset's thumbnail, once it has one (see [Thumbnails](../content/daemon-and-operations.md#thumbnails)), or for a file with none, such as a stage, its prefab's or its first mesh's. A grid tile that shows asks `ThumbnailQueue` for a picture that the host must draw, a part of a prefab's too, and shows it when the answer comes, with no new rows. `ThumbnailCache` decodes the files off the UI thread and keeps what has shown for a while. Each has an icon for its kind where it has no picture, its name, and a mark when it failed or has errors or warnings, and a list row also its behaviour's class. Both are one virtualized stack of rows of equal height, as Avalonia has no virtualizing wrap panel, so where an asset is follows from its index, whatever is realized.
- **Selecting:** a click selects an asset, Ctrl adds or removes one, and Shift takes the assets from the last one clicked. The arrows, Page Up, Page Down, Home and End move the selection, and with Shift grow it. Ctrl+A selects all that show. A drag in the empty space selects with a marquee, which scrolls at the edges, and with Ctrl adds to the selection. A click in the empty space ends it.
- **Sub-assets:** a file with sub-assets, such as a glTF model or a USD stage, has an arrow that shows them in place of its folder's assets (see [Content pipeline](../content/identity-and-cooking.md#identity)), as does a double click on one with no editor, and Show Contents in its menu. The path over the assets gains the file, and Backspace goes back. A prefab has the same arrow, to its entities, and a stage's prefab comes first in what the stage makes (see [Prefabs](prefabs.md#panels-and-the-viewport)). A sub-asset selects, drags onto an asset field and shows its details like any asset. Revealing one opens its file. The operations act on its file, so Rename, Duplicate and Delete are offered on the file only.
- **Filter:** a chip for each kind of asset, with how many there are, narrows what shows, several at once. A kind groups what a person looks for together: Materials are materials, instances and functions, and Models are models and stages. **Search** matches every word of the query against an asset's name or behaviour class, and a `kind:` word, such as `kind:script`, filters by exact kind. A filter looks in every folder, or with In This Folder in the open folder and those under it. In an open file it looks only in the file, and leaving the file ends it. Clear ends a filter.
- **Tags:** a project's own names for its assets, which nest: `env/stone/trim` is under `env/stone`, and a tag matches those under it. The left of the panel shows the folders or the tags, each tag with how many assets have it or one under it. A click filters by a tag, and several narrow further, and an asset dragged onto a tag gets it. A tag's menu renames it with those under it, or takes it from its assets. The details show the selected assets' tags as chips, dim when only some of them have one, which a click gives to all, with a cross that takes it from all, and a box adds one. A `tag:` word in the search does the same as a click. What a file has, the sub-assets that it makes have. A copy has its source's tags.
- **Where tags live:** `project.tags` beside `project.settings`, which a team commits, in the lines of `ProjectTags` in `Cinnabar.Editor.Content`: `<guid> = env/stone/trim, review/todo`, with `#` comments. It is keyed by GUID, so a move keeps an asset's tags, and it is not content, so a change cooks nothing and the daemon never reads it. It cannot be in `.meta` files, whose every edit cooks most kinds again and which sub-assets do not have. A new line goes in GUID order, so two people who tag different assets merge cleanly. An asset that is gone keeps its line, because the Recycle Bin can bring it back. The editor reads the file again when its window activates and after a cook, as a pull can change it, and before each edit, so it does not undo another program's.
- **Details:** the selected asset's path, GUID, status, behaviour, tags, import settings, the assets that it depends on and those that use it, as links that select them, and its problems. Clicking a problem opens its file in the script editor at its line.
- **Import settings:** each setting that the selected files all take, with the same values, has an editor: a check box for a setting of true or false, and a list of its values otherwise, with the setting's description as its tooltip. A setting in a section has a key such as `mip_map.border`, and shows under the section's header, as Mip map, with the label Border. An editor shows no value while the files differ, and a change sets it for all of them, leaving what differs elsewhere as each file has it. `ImportSettingsDraft` keeps the changes, each marked with a dot, until Apply sends them to the daemon in one message, because a change can mean a long cook. Apply and Revert stay in sight over the settings. Moving the selection off those files asks whether to apply them, discard them or keep editing, and closing the dialog keeps editing. A sub-asset's settings are its file's, so it shows a link to the file. Closing the editor discards a draft without asking.
- **Problems** are in the daemon's log, which the console shows, with their file and line. An asset with problems shows them in its tooltip too.
- **Opening:** double-clicking a scene or a prefab opens it, and asks first to save unsaved changes. What a stage generates, its prefab and its material instances, opens from its generated text with a warning, because the stage's next cook replaces that text. Double-clicking a material graph or a material function opens it in the material editor, an animation graph in the [animation graph editor](animation-graph-editor.md#animation-graph-editor), a UI document in the [UI editor](ui-editor.md#ui-editor), an effect in an effect preview (see [Rendering](../rendering/particles.md#previews)), and a script, a shader, a shading model, a material written in HLSL or a material instance in the script editor. An asset's menu also shows it in Explorer, and copies its GUID or its path.
- **The script editor** is `"scriptEditor"` in `settings.json` in the editor's settings: an array of the program and its arguments, in which `{file}` and `{line}` stand for the script's path and a line, such as `["code", "-g", "{file}:{line}"]`, the default. The editor runs it through `cmd /c`, as VS Code's `code` is a batch file.
- **Dragging:** a script that defines a behaviour drags onto an entity in the outliner, or onto the properties panel, which adds the behaviour to each selected entity that lacks it, in one undo entry. Assets drag onto a folder in the content browser, which moves them there. A drag of a selected asset takes the whole selection. An asset drags onto an asset reference field of its kind, and a material onto the viewport (see [Viewport](viewport.md#viewport)).
- **Operations:** no operation has the editor write a `.meta` file. Each operation sends its message to the daemon, which does it, and awaits the answer (see [Content pipeline](../content/daemon-and-operations.md#asset-operations)). The commands are New Script, New Behaviour, New Scene, New Material, New Material Function, New Mesh, New Prefab and New Folder, which ask for a name and make it in the content browser's folder, and Rename Asset (F2), Duplicate Asset (Ctrl+D), Delete Asset (Delete) and Re-import, which act on the selected assets. They are in the command palette and the content browser's menus. Their keys work while the content browser has focus, because the same keys act on entities elsewhere. A key that means both is a binding on the panel, since a window's key bindings come before the focused control sees the key and the nearest binding comes first; with no asset to act on, it does nothing rather than act on the entities. For the same reason no shortcut that a text box uses runs while one has the focus, so Delete in a search box edits the text. A folder's menu also renames and deletes it. Delete shows the assets that use what it takes, which will fail to cook, and confirms. A move or a rename that breaks requires lists the scripts that have them, and asks whether the daemon rewrites them; a dialog then shows each rewritten require (see [Content pipeline](../content/daemon-and-operations.md#moved-modules)). When the daemon refuses an operation, the editor shows its reason, and the console has it. Without the cook link, the operations are disabled.
- **No undo:** asset operations change the project, not the scene, so they are not on the undo stack. The Recycle Bin has what a delete takes.
- **Missing scripts:** a delete does not change the scenes that use what it takes. A behaviour whose script is no longer in the content shows in the properties panel as a missing script, with its GUID and the values that the scene keeps, and a button that removes it. Restoring the script from the Recycle Bin brings the behaviour back. A behaviour that the scene names and the game did not attach shows the same way.
- **The open scene follows its file:** when a move or a rename takes the open scene's file, the document takes the new path, and so does its autosave.
- **Saving scenes:** the editor writes a scene's text, the one content file that it writes. A new scene in a root gets its `.meta` file at the daemon's next pass.
- **Without the daemon:** while the cook link is down, the content browser keeps its last index, dimmed.
- **Panel ID:** the panel is `contentBrowser`. A saved layout from an older editor names it `assetBrowser`, and the editor reads that as the new ID.
